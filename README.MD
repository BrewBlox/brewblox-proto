# Shared interface types for Brewblox

The repository is split in three parts:

`/proto` contains the protobuf message definitions. These are the source of
truth: the firmware, the service and the TypeScript types are all derived
from them.

`/ts` contains TypeScript enum and type definitions. The block types are
generated from `/proto`; the rest is hand-written.

`/docs` contains JSON/YAML data to build documentation.

## Generated TypeScript

`ts/spark-block-types.ts` and `ts/spark-block-enums.ts` are generated by
`scripts/generate-ts.mjs` from `proto/*.proto`. Do not edit them by hand.

```sh
yarn install
yarn generate
```

CI runs the generator and fails when the committed `ts/` differs from the
output, so a proto change cannot ship without matching types.

The generator maps the custom field options declared in `brewblox.proto` to
TypeScript conventions: `unit` becomes `Quantity`, `objtype` becomes `Link`,
`readonly` wraps the type in `Readonly<>`, `datetime` becomes
`DateString | null`, `hexed`/`hexstr`/`ipv4address` become `string`,
`omit_if_zero` makes the property optional, `null_if_zero` adds `| null` to
each element (so a repeated field becomes `(T | null)[]`),
`bitfield` becomes `number` (or the flag enum named in the generator's
bit-field table), and `ignored` fields are skipped. `scale`, `logged`,
`stored`, `skip_changed` and `changed` have no effect on the types: `scale`
only changes the wire integer (the service divides it out), `logged` selects
what the service publishes to history, `stored` what a stored read returns,
and `skip_changed`/`changed` select the fields of a changed read (Read modes,
below).
A `message Block` with `(brewblox.msg).objtype = X` becomes
`XBlock extends Block { type: 'X'; data: {...} }`. Enums become
`typescript-string-enums` enums with the first declared name for each value.

Everything the proto files cannot express is kept in commented tables at the
top of the script: the interface blocks (`EnablerInterfaceBlock`, ...), the
`BlockIntfType` and system block lists, the bit-flag enums, message and enum
renames, and a handful of per-field conventions (nullable digital states,
optional constraint members, `Sequence.instructions` as `string[]`). Add a
table entry when a new proto construct needs a convention; the generator
fails on anything it does not have a rule for.

The `// #region Name` markers are a documentation contract: the
documentation site includes them verbatim. The generator refuses to drop an
existing region unless it is run with `--allow-region-removal`.

## Hand-written TypeScript

These files are not generated:

- `ts/spark-service-types.ts`: service API types
- `ts/spark-block-const.ts`: `COMPATIBLE_TYPES` and the channel name tables
- `ts/automation-types.ts`, `ts/generic-types.ts`, `ts/index.ts`

## Get started

Install protobuf compiler:

sudo snap install --classic protobuf

## Read modes

`ReadMode` in `command.proto` selects the fields a block read returns:

- `DEFAULT`: every readable field.
- `STORED`: the fields marked `stored`, what the controller persists.
- `CHANGED`: the fields marked `readonly` or `changed` and not `skip_changed`, without the
  block name. A `BLOCK_READ_ALL` in this mode returns only the blocks whose CHANGED fields
  differ from what the previous CHANGED read-all on the same connection returned. The first
  CHANGED read-all on a connection returns every block, and so does one from any other
  connection than the one that did the previous CHANGED read-all: one reader per controller.
  The service polls with this read every second; a `DEFAULT` read every few seconds, at
  connect and after any error is its baseline and its recovery.

Decoding a CHANGED payload:

- A message-typed field is traversed when any field below it is covered, and carries only
  covered fields. A covered field absent from the payload is zero, whether or not its
  parent is present; an EXCLUSIVE mask entry marks a field invalid, as in every mode.
- A repeated message field is included when any field below it is covered, with complete
  elements: the list replaces the previous one as a whole.
- `skip_changed` on a message-typed field prunes its subtree.
- A block without any covered field never appears in a CHANGED read-all.

The field options behind it:

- `skip_changed`: a readonly field left to the full read (clocks, counters, readings).
- `changed`: a writable field the firmware moves by itself (a Sequence instruction, a
  claim), so a changed read reports it.
- `logged`: what the service publishes to history. It does not affect what the firmware
  sends.
